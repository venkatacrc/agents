You know training and inference. This lesson connects them to everything you've built: why models are good at the loop at all, and what the loop does to a serving system.

## Training: from base model to agent

A base model has never seen `<tool_call>`. Agentic behavior comes from post-training in roughly three stages.

**1. SFT on trajectories.** Collect agent runs (human-written, or generated by a stronger model and filtered for success), render them with the chat template (lesson 00), and fine-tune. The key detail is the **loss mask**: the loss is only on tokens *the model wrote*: its reasoning, its tool calls, and the `<|im_end|>` that teaches it to stop. System prompts, user turns and tool results are context, not targets. Training on tool results would teach the model to *hallucinate* tool outputs instead of waiting for them.

**2. RL with verifiable rewards (RLVR).** Sample many rollouts per task in a real environment (a repo with tests, a sandbox with tools, a simulated user) and score each one with a program: tests pass, the answer matches, the database is in the right state. DeepSeek-R1 showed how far this goes for reasoning; agentic models (Claude, the o-series and gpt-oss, Kimi K2, Qwen3, GLM) are trained with large-scale RL in tool environments. The reward is where you encode what "good" means, including cost: a penalty per step teaches efficiency.

**3. GRPO-style advantages.** Group Relative Policy Optimization (DeepSeekMath, 2024) drops PPO's value network. For each task it samples a *group* of \(G\) rollouts and uses the group as the baseline:

\[ A_i = (r_i - \mathrm{mean}(r)) / (\mathrm{std}(r) + \epsilon) \]

Rollouts better than their siblings get pushed up, and worse ones down. If every rollout gets the same reward (all succeed or all fail), every advantage is zero and the task teaches nothing. That's why curricula keep tasks at the edge of the model's ability.

**Reward hacking** is the constant enemy: models learn to special-case tests, skip verification, or claim success. Environments need verifiers that can't be gamed, and that's much of the engineering effort in agentic RL.

## Serving: the loop meets the KV cache

Each agent step is a new request whose prompt is the previous prompt plus a bit more (lesson 02). Without help the server re-prefills everything every step: \(O(\text{steps}^2)\) prefill compute. **Prefix caching** fixes this. vLLM's automatic prefix caching hashes KV blocks, and SGLang's RadixAttention keeps a radix tree of cached prefixes. If the new prompt starts with tokens already in the cache, their KV is reused and only the new suffix is prefilled. Providers bill cached input tokens at a steep discount (often 75–90% off) for the same reason.

That puts a constraint on the harness: **the prompt must be append-only**. Anything that changes an early token invalidates everything after it:

- a timestamp or random id in the system prompt,
- tools listed in a different order (a set or dict that isn't ordered deterministically),
- rewriting old tool results, or compaction (which rewrites the middle, deliberately trading a cache miss for a smaller context).

Claude Code, Codex and Cursor go to some lengths to keep their prefixes stable for exactly this reason.

::: explain
**Only 17% of a trajectory is training signal.** The system prompt with tool schemas, the question and the tool results are 83% of the tokens and carry no loss. The trained spans are just the three assistant turns (two lookups in parallel, the calculator call, the final sentence), each ending in `<|im_end|>`. Long agent trajectories are expensive to train on per useful token, which is one reason RL (which only needs the reward) scales better than collecting perfect demonstrations.

**GRPO ranked the behaviors without a value model.** Parallel lookups (+0.80) beat sequential ones (+0.55) only because of the step penalty, and the reward never mentioned parallelism. Mental math scored −1.65, the strongest signal in the group. The dithering-but-correct rollout landed slightly below average (−0.18): right answer, too many steps. Change the step penalty to 0 and parallel and sequential become identical, which is how reward design shapes behavior.

**86% of prompt tokens served from cache, append-only.** Each request re-uses everything up to the new tool result. Put `Current time: 06:00:07` at the start of the system prompt and the hit rate collapses to 0.4%: the first few tokens differ, so nothing after them matches. Rotating the tool order is nearly as bad (3.9%). Rewriting old results lands in between (56%), because the prefix still matches up to the first rewritten message.

**Compaction is a deliberate cache miss.** Lesson 04 rewrote the middle to keep the context small; this lab shows what that costs at the server. Good harnesses compact rarely and in big steps, so each compaction is followed by many append-only, cache-friendly requests.
:::

::: cards
Q: In SFT on agent trajectories, which tokens get loss?
A: Only the assistant's own tokens: its reasoning, its tool calls and the end-of-turn token; not system, user or tool-result tokens.
Q: Why must tool results be masked out of the SFT loss?
A: Training on them would teach the model to generate (hallucinate) tool outputs itself instead of stopping and waiting for real results.
Q: What is RL with verifiable rewards (RLVR)?
A: Reinforcement learning where rollouts are scored by a program (tests pass, answer matches, state is correct) rather than a learned reward model.
Q: Write the GRPO advantage.
A: For a group of G rollouts of the same prompt, A_i = (r_i − mean(r)) / (std(r) + ε); the group is the baseline, with no value network.
Q: What happens in GRPO when every rollout in a group gets the same reward?
A: All advantages are zero, so the task contributes no gradient. Tasks must be neither always solved nor never solved.
Q: What is prefix caching, and why do agents benefit so much?
A: Reusing the KV cache of a prompt prefix already computed; agent steps share almost their whole prompt with the previous step.
Q: Name three harness habits that destroy prefix-cache hits.
A: A timestamp or random id early in the prompt, non-deterministic tool ordering, and rewriting earlier messages (including compaction).
Q: What is reward hacking in agentic RL?
A: The policy maximizing the reward without doing the task, e.g. special-casing tests or claiming success, exploiting a weak verifier.
:::
